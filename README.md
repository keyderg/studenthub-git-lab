# Checklist de evaluación

## Repositorio local

* \[v] Se ejecutó `git init`.
* \[v] Se creó al menos un archivo.
* \[v] Se utilizó `git add`.
* \[v] Se realizaron varios `git commit`.
* \[v] Se utilizó `git diff`.
* \[v] Se consultó `git status`.

## Ramas

* \[v] Se utilizó `git branch`.
* \[v] Se utilizó `git checkout`.
* \[v] Se utilizó `git checkout -b`.
* \[v] Se trabajó con al menos dos ramas diferentes de `main`.

## Integración

* \[v] Se ejecutó `git merge`.
* \[v] Se provocó un conflicto.
* \[v] El conflicto fue resuelto manualmente.
* \[v] Se ejecutó `git rebase`.

## Repositorio remoto

* \[v] Se creó un repositorio en GitHub.
* \[v] Se utilizó `git remote add origin`.
* \[v] Se utilizó `git push`.
* \[v] Se utilizó `git pull`.
* \[v] Se utilizó `git clone`.

## GitHub

* \[v] Se creó un Pull Request.
* \[v] Otro estudiante revisó el Pull Request.
* \[v] Se solicitó al menos un cambio.
* \[v] El autor corrigió el cambio solicitado.
* \[v] El reviewer aprobó el Pull Request.
* \[v] El Pull Request se integró a `main`.

### 1\. ¿Cuál es la diferencia entre `git add` y `git commit`?

\---

&#x20;      R/ el git add prepara los cambios realizados para guardarlos mientras que el git commit es que se encarga de guardarlos.

### 2\. ¿Cuál es la diferencia entre `git push` y `git pull`?

\---

&#x20;      r/ git push sirve para enviar desde el repositorio local al remoto y el git pull es para bajar del repositorio remoto al local

### 3\. ¿Cuál es la diferencia entre un repositorio local y uno remoto?

\---

&#x09;r/ el repositorio local es el que esta en mi computadora donde estoy trabajando, mientras que el remoto se encuentra en una pagina para que se almacene como en la nube

### 4\. ¿Qué problema resuelve una rama?

\---

&#x09;R/ resuelve problemas de organización, lo cual ayuda mucho a las personas porque todos tendemos a equivocarnos y la rama hace que tengamos mas seguridad y sea mas difícil perder información.

### 5\. ¿Qué diferencia existe entre `git merge` y `git rebase`?

\---

&#x09;R/ tengo entendido que el git merge hace la unión de las dos ramas y de los dos historiales, mientras que el git rebase hace que al unir las ramas se vayan poniendo los commits en orden uno a uno para que quede mas limpio, pero sinceramente no me queda muy claro del todo al usarlo.

### 6\. ¿Por qué ocurre un conflicto?

\---

&#x09;R/ Un conflicto ocurre cuando tratamos de hacer un push a un archivo que fue modificado después que yo hice un pull a ese mismo.

### 7\. ¿Quién debe decidir cómo resolver un conflicto?

\---

&#x09;R/ tengo entendido que el conflicto lo resuelve el que intenta hacer el push, ya que el es el ultimo en querer modificar.

### 8\. ¿Qué problema resuelve un Pull Request?

\---

&#x09;R/ el pull request sirve para evitar conflictos como el anterior y evitar que se hagan cambios grandes de la nada sin que todos se enteren

### 9\. ¿Por qué es recomendable revisar un Pull Request antes de integrarlo?

\---

&#x09;R/ porque nos dice que cambios se quieren aplicar y nosotros debemos decidir si es conveniente o no.

### 10\. ¿Qué ventaja tiene trabajar en una rama en lugar de modificar directamente `main`?

\---

&#x09;R/ trabajar en una rama y no en el main no permite no afectar nuestro base del trabajo, por seguridad de no hacer algo o mal o sin querer borrar cosas, se recomienda crear una rama para y luego de hacer lo que queríamos hacer y que este todo bien hacer un merge o un rebase.
